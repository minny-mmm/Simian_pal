# การทำ feature (คู่มือ + ปัญหาที่เจอ)

คู่มือสำหรับคนที่จะเขียนขั้นสกัด feature ต่อจากผล clean เพื่อทดลองแยกกลุ่ม PD (COPS) จากกลุ่มควบคุมที่คัดจาก NHANES
label ของ NHANES เป็นผลจากเกณฑ์คัดเลือก ไม่ใช่หลักฐานยืนยันว่าไม่มี PD และ dataset/อุปกรณ์ซ้อนกับ label ทั้งหมด
**ใน repo ยังไม่มีโค้ด feature** (โค้ดต้นแบบเดิม `tools/feature_check.py` และ `s3_batch.py features` ถูกเอาออกแล้ว
เพราะมีปัญหาตามหัวข้อ "ปัญหาที่เจอ" ด้านล่าง ดูโค้ดเดิมได้ใน git history: `git show 65de488:tools/feature_check.py`)

ตรวจต้นทางก่อนทำ feature ด้วย `python tools/audit_sources.py` ดูขั้นตอนและผลตรวจวันที่ 19 ต.ค. 2026 ใน [README_audit.md](README_audit.md)
ผลจะอยู่ใน `reports/source_audit/`: รายคน, จำนวนแยก label/dataset/อุปกรณ์/split, ประเด็นผิดปกติ และแผนทดลอง
เก็บ `still_frac` และ `rest_tremor_ratio` ไว้ในไฟล์ตรวจแยกจาก baseline เสมอ ห้ามใช้ผล feature เก่าที่ชั่วโมงซ้ำเป็นชุดหลัก

## 1. input: ผล clean

ดึงจาก S3: `python tools/s3_pull.py get --what clean --dataset cops` (และ `--dataset nhanes`)

| ไฟล์ | ใช้ทำอะไร |
| --- | --- |
| `data/clean/<ds>/<id>.qc.json` | **อ่านก่อน** ข้ามคนที่ `"included": false` (วันใช้ได้ < 3) |
| `data/clean/<ds>/<id>.parquet` | สัญญาณ 50 Hz คอลัมน์ `time_s, x, y, z` (g), `valid`, `reason`, `day`, `visit` (~30 ล้านแถว/คน) |

**กฎ**
1. ใช้เฉพาะแถว `valid = True` (ตื่น + ใส่นาฬิกา + อยู่บ้าน + ไม่ติดธงผิดปกติ)
2. ข้ามคนที่ `included = false`
3. **แบ่งวันจากคอลัมน์ `day` ห้ามถือว่า 1 row group = 1 วัน** (ดูปัญหาข้อ 1)
4. แบ่ง train / valid / test ด้วยคอลัมน์ `split` จาก `metadata/cops_splits.csv`, `metadata/nhanes_splits.csv`
   **ตามคน** ห้ามสุ่มรายชั่วโมง / รายหน้าต่าง (คนเดียวกันจะอยู่ทั้ง train และ test)
5. ค่ากลางทุกอย่างที่คำนวณจากข้อมูล (เกณฑ์, ค่า normalize, การเลือก feature) ใช้ **เฉพาะ train**

อ่านทีละวัน (RAM ไม่เต็ม)

```python
import json
import pyarrow.parquet as pq

qc = json.load(open("data/clean/cops/COPS-8.qc.json"))
if qc["included"]:
    for d in [x["day"] for x in qc["days"] if x["valid"]]:            # เฉพาะวันที่ผ่านเกณฑ์
        df = pq.read_table("data/clean/cops/COPS-8.parquet",
                           columns=["time_s", "x", "y", "z", "valid"],
                           filters=[("day", "=", d)]).to_pandas()
        df = df[df["valid"]]
        # ... หั่นหน้าต่าง / คำนวณ feature ...
```

## 2. แนวทางที่แนะนำ

```
ผล clean (50 Hz, valid)
  -> หั่นหน้าต่าง 10 วิ (500 sample) ตามเวลา: window = floor(time_s / 10)
     ใช้เฉพาะหน้าต่างที่ valid ครบ 500 sample (ไม่ต่อหน้าต่างข้ามช่วงที่ถูกตัด)
  -> จำแนกหน้าต่าง: เดิน / พัก / ขยับทั่วไป
  -> feature ต่อหน้าต่าง
  -> รวมเป็นรายชั่วโมง (หรือรายวัน / รายคน) ด้วย median / percentile / จำนวน
  -> 1 แถว = 1 ชั่วโมง: subject_id, dataset, label (1 = PD), split, day, hour, valid_min, feature...
```

feature ที่ต้นแบบเดิมใช้ (แนวคิดยังใช้ได้ แต่ต้องแก้ปัญหาด้านล่าง)

| feature | สูตร (ต่อหน้าต่าง) | เกี่ยวกับ PD |
| --- | --- | --- |
| ENMO | mean(max(‖a‖ − 1, 0)) | เคลื่อนไหวน้อย / ช้า |
| มุมแกว่งแขน | P95 − P5 ของมุมระหว่างทิศแรงโน้มถ่วง (ค่าเฉลี่ย 0.25 วิ) กับทิศเฉลี่ยของหน้าต่าง (เฉพาะหน้าต่างเดิน) | แขนแกว่งน้อย |
| jerk | mean(\|Δ‖a‖\|) × fs [g/s] | ขยับช้า ไม่กระฉับกระเฉง |
| จับการเดิน | autocorrelation รวม 3 แกน สูงสุดที่ lag 0.35–1.3 วิ (0.75–2.9 Hz) + ความแรงหลังหักค่าเฉลี่ย 1 วิ | จำนวนการเดิน |
| อาการสั่นตอนพัก | พลังงาน 3.5–7.5 Hz (Hann window) ในหน้าต่างพัก | rest tremor 4–6 Hz |
| ความถี่หลัก | argmax ของสเปกตรัมช่วง 1–15 Hz | |

## 3. ปัญหาที่เจอ (ต้องแก้ / ระวัง)

### 3.1 ชั่วโมงแตกเป็น 2 แถว (row group ≠ วัน) — **บั๊ก ยืนยันแล้ว**
`write_parquet` เขียนทีละวัน แต่ pyarrow ตัด row group เองทุก 1,048,576 แถว (~5 ชม. 49 นาที)
1 วันมี 4–5 row group รอยตัดอยู่ที่ ~05:49, 11:39, 17:28, 23:18 ต้นแบบเดิมอ่านทีละ row group แล้วแบ่งชั่วโมงในก้อน
ชั่วโมงที่คร่อมรอยตัดจึงได้ **2 แถวซ้ำ แต่ละแถวข้อมูลไม่ครบ** และหน้าต่าง 10 วิไม่ตรงขอบ

ตัวอย่าง COPS-8: 10 จาก 48 แถว (~20%) เช่น day 4 hour 11 = 38.7 นาที **และ** 20.3 นาที

**แก้:** อ่านทีละวันด้วย `filters=[("day", "=", d)]` (ตัวอย่างข้อ 1) หรือรวมก้อนก่อนแบ่งด้วย `time_s`

### 3.2 `rest_tremor_ratio` วัดได้แต่ noise ของเซ็นเซอร์
สัดส่วนพลังงาน 3.5–7.5 Hz ต่อ 1–15 Hz ของ white noise = (7.5 − 3.5) / (15 − 1) = **0.29**
ค่าจริงของ COPS-8 ทุกชั่วโมง = 0.27–0.32 (= noise ล้วน) เพราะหน้าต่าง "พัก" แทบไม่มีการขยับ
- แทบไม่มีข้อมูลเรื่องโรค และ **ขึ้นกับ noise ของเครื่อง** (noise ที่เติมให้ NHANES เป็น white Gaussian ส่วน GENEActiv อาจไม่ใช่)

**แก้:** คิด ratio เฉพาะหน้าต่างที่พลังงานช่วงสั่นสูงกว่า noise ชัดเจน (เช่น `tremor_rms` > 15 mg) หรือใช้แค่จำนวน / สัดส่วนหน้าต่างที่สั่น

### 3.3 `still_frac` และตัวกรอง `still_frac < 0.9` ไม่มีผล
เกณฑ์ "นิ่ง" (ทุกแกนเปลี่ยน ≤ 50 mg ใน 10 วิ) = เกณฑ์ธง `ism` ในขั้น clean หน้าต่างนิ่งจึงถูกตัดไปแล้ว
หลัง clean ค่านี้อาจเป็น ~0 (มาจากต้นแบบที่อ่านไฟล์ดิบ) **แยกออกจากชุดหลัก แต่เก็บไว้ตรวจ**
ทดลอง baseline ที่ไม่ใช้ทั้ง `still_frac` และ `rest_tremor_ratio` แล้วเพิ่มกลับทีละตัวและทั้งคู่ โดยใช้คนและ split เดิม
ค่าที่ดีขึ้นในข้อมูลที่ label ซ้อนกับอุปกรณ์ยังไม่พิสูจน์ว่าแยกโรคได้ ต้องมีทั้งสองกลุ่มบนอุปกรณ์เดียวกันเพื่อสรุปเรื่องนี้

### 3.4 เกณฑ์ส่วนใหญ่ไม่มีที่มา และยังไม่ได้ทดสอบ

| มีที่มา | กะเอง (ต้องทดสอบ) |
| --- | --- |
| นิ่ง ≤ 50 mg (ดัดแปลงจากเกณฑ์ถอดนาฬิกา van Hees / GGIR ซึ่งใช้หน้าต่าง 60 นาที) | เดิน: `step_ac > 0.5`, `dyn_rms > 0.12 g` |
| สั่น 3.5–7.5 Hz (rest tremor ของ PD ~4–6 Hz) | พัก: มุม < 15°, `dyn_rms < 0.08 g` |
| จังหวะก้าว 0.75–2.9 Hz (สรีรวิทยาการเดิน) | สั่น: `tremor_ratio > 0.5`, `tremor_rms > 0.015 g` |
| ช่วงอ้างอิง 1–15 Hz | ชั่วโมงต้องมีหน้าต่างใช้ได้ ≥ 30 (5 นาที) |

**ทดสอบด้วยข้อมูลที่มี (ใช้แค่ train):**
- สั่น: diary ของ COPS มี `TremorScore` รายชั่วโมง (0–2) → เทียบกับจำนวนหน้าต่างที่สั่น
  (ต้องเพิ่มการอ่านคะแนนจาก diary ก่อน: `src/ingestion/cops_reader.py` → `hour_labels` ปัจจุบันคืนเฉพาะ hour, visit, diary_sleep ไม่คืน TremorScore)
- เดิน: ดูด้วยตาจากกราฟ หรือเทียบกับจำนวนก้าวที่คาด

### 3.5 ไม่มี band-pass
เอกสารเดิมบอก band-pass 0.5–15 Hz ตอนทำ feature แต่ต้นแบบไม่มี (ใช้หักค่าเฉลี่ย 1 วิ + เลือกช่วงความถี่ในสเปกตรัมแทน)
ตัดสินใจให้ชัดว่าจะใช้หรือไม่ และใช้แบบเดียวกันทั้งสองชุด

### 3.6 feature ที่ใช้ขนาดสัญญาณไวต่อยี่ห้อนาฬิกา
ActiGraph อ่านค่าต่ำกว่า GENEActiv ~10% ที่ข้อมือ และตัวกรองในเครื่องต่างกัน (80 vs 100 Hz)
ENMO, jerk, ความแรง จึงอาจแยกยี่ห้อได้แม้ไม่มีโรค feature ด้านความถี่ / มุม ข้ามยี่ห้อได้ดีกว่า

## 4. ต้องตรวจก่อนเทรน: โมเดลเรียนโรค ไม่ใช่ยี่ห้อ

PD ทุกคนใส่ GENEActiv คนปกติทุกคนใส่ ActiGraph ยี่ห้อกับโรคซ้อนกัน 100% (ดู README.md หัวข้อ "การปรับ noise")

1. **LR แยกยี่ห้อบน feature จริง** (โดยเฉพาะช่วงนิ่ง / พัก) feature ไหน AUC > 0.7 ให้ตัดหรือปรับ
   ผลเดิม: SD 3 แกนในช่วงนิ่งหลังปรับ noise ต่อแกน AUC 0.49, feature หน้าต่าง 10 วิทั้งวัน ~0.60 (ก่อนปรับต่อแกน ต้องวัดซ้ำ)
2. **ชุดทดสอบที่ยี่ห้อไม่ซ้อนกับโรค**
   - NHANES ที่กิน levodopa (PD ที่ใส่ ActiGraph) SEQN 73725, 78144, 78486 ถ้าโมเดลทายว่า PD บ่อยกว่าคนปกติ = เรียนโรคได้จริง
     (ไม่อยู่ใน `nhanes_splits.csv` ต้องโหลดและ clean แยก จำนวนน้อย ใช้ได้แค่ตรวจเบื้องต้น)
   - ข้อมูลที่ PD กับคนปกติใส่นาฬิการุ่นเดียวกัน เช่น UK Biobank (Axivity)

## 5. ทำงานเป็นทีม

- ผล feature เก็บที่ S3 `data/features/<ds>/<id>.csv` (layout เดียวกับในเครื่อง อัปด้วย `python tools/s3_sync.py push data/features`)
- บันทึกเวอร์ชันโค้ด (git commit) และเกณฑ์ที่ใช้ไว้คู่กับผล ถ้าแก้สูตร ต้องทำใหม่ทุกคน
- ถ้าผล clean เปลี่ยน (เช่น clean NHANES ใหม่หลังเปลี่ยนเป้า noise) feature ของคนนั้นต้องทำใหม่ด้วย
