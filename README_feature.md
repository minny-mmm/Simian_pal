# Feature: สิ่งที่คนเทรนโมเดลต้องรู้

ขั้น feature แปลงผล clean (สัญญาณ 50 Hz) เป็นตาราง 1 แถวต่อ 1 ชั่วโมง ใช้เป็น input ของโมเดลแยก PD (COPS) จากคนปกติ (NHANES)
โค้ดอยู่ที่ `src/features/run.py` ใช้โค้ดและเกณฑ์ชุดเดียวกันทั้งสองชุดข้อมูล

---

## 1. ไฟล์และวิธีได้มา

```bash
python tools/s3_sync.py pull data/features            # ดาวน์โหลดจาก S3
python -m src.features.run --dataset cops             # หรือสร้างเองจากผล clean
python -m src.features.run --dataset nhanes
python -m src.features.run --dataset cops --ids COPS-8 --force   # ทำใหม่เฉพาะคน
```

- ไฟล์: `data/features/<dataset>/<subject_id>.csv` 1 ไฟล์ต่อคน
- คนที่ `included = false` ใน qc.json (วันใช้ได้ไม่พอ) ไม่มีไฟล์
- ถ้าแก้โค้ด feature หรือผล clean เปลี่ยน ต้องสร้างใหม่ทุกคน

## 2. ข้อมูลในไฟล์มาจากไหน

ทุกแถวคำนวณจากข้อมูลที่ผ่านการกรองแล้วเท่านั้น

1. เฉพาะแถว `valid = True` ของผล clean (ตื่น, ใส่นาฬิกา, อยู่บ้าน, ไม่มีสัญญาณผิดปกติ)
2. เฉพาะวันที่ผ่านเกณฑ์ใน qc.json
3. **เฉพาะ 09:00–21:00** ตัวจับการนอนพลาดช่วงกลางคืนของคนไข้ PD บ่อย (นอนแบบตื่นบ่อย) ใช้ช่วงกลางวันเหมือนกันทั้งสองชุดจึงปลอดภัยกว่า
4. หั่นเป็นหน้าต่าง 10 วินาที ใช้เฉพาะหน้าต่างที่ข้อมูลครบ ไม่ต่อข้อมูลข้ามช่วงที่ถูกตัด
5. จัดประเภทหน้าต่าง (หัวข้อ 4) คำนวณ feature ต่อหน้าต่าง แล้วรวมเป็นรายชั่วโมงด้วย median / percentile / สัดส่วน
6. ชั่วโมงที่มีหน้าต่างใช้ได้น้อยเกินไปถูกตัดทั้งแถว **ชั่วโมงที่ไม่มีในไฟล์ = ข้อมูลไม่พอ** ไม่ใช่ศูนย์

### ทำไมถึงมี feature เหล่านี้

feature แต่ละกลุ่มเลือกมาให้ตรงกับอาการหลักของ PD ที่นาฬิกาข้อมือวัดได้

| กลุ่ม | อาการ PD ที่ต้องการจับ | เหตุผล |
| --- | --- | --- |
| สัดส่วนเวลา | เคลื่อนไหวน้อย, เดินน้อย, มีอาการสั่น | PD มักเดินน้อยลงและนั่งพักนานขึ้น `tremor_frac_*` คือ "เวลาที่สั่น" ซึ่งงานติดตาม tremor จากนาฬิกาข้อมือใช้เป็นตัววัดหลัก |
| การขยับทั่วไป | Hypokinesia (ขยับน้อย / เบาลง) | วัดปริมาณและความแรงของการเคลื่อนไหวทั้งวัน `jerk` บอกว่าขยับกระฉับกระเฉงหรือช้า |
| รูปแบบสัญญาณ | การเคลื่อนไหวที่หลากหลายน้อยลง | `spec_entropy` บอกว่าการขยับกระจายหลายความถี่หรือซ้ำ ๆ แบบเดิม |
| Bradykinesia | ขยับช้าและเบาลง (bradykinesia) | วัดแรงของการขยับมือในกิจกรรมที่ไม่ใช่การเดินและไม่ใช่การสั่น แยกออกจากการเดินเพื่อไม่ให้ปริมาณการเดินกลบอาการ |
| การเดิน | เดินผิดปกติ, แกว่งแขนน้อย | PD มีจังหวะก้าวเปลี่ยนไป ความแปรปรวนของจังหวะสูงขึ้น ความสม่ำเสมอลดลง (วัดด้วย autocorrelation ตาม Moe-Nilssen & Helbostad 2004) และแกว่งแขนน้อยลง ซึ่งเป็นอาการที่เห็นได้ตั้งแต่ระยะแรก ใช้เฉพาะหน้าต่างเดินเพื่อให้เทียบกันได้ |
| Tremor | Rest tremor (สั่นขณะพัก) | อาการเด่นของ PD สั่นที่ราว 4–6 Hz ตอนแขนวางนิ่ง วัดทั้งความแรง สัดส่วนพลังงาน และความถี่ของการสั่น |

ข้อสังเกต: ไม่ใช่คนไข้ PD ทุกคนจะมีทุกอาการ เช่นกลุ่ม akinetic-rigid แทบไม่มี tremor จึงต้องใช้หลายกลุ่มร่วมกัน

## 4. การจัดประเภทหน้าต่าง

ตรวจตามลำดับนี้ (เกณฑ์อยู่ใน `CFG` ของ `src/features/run.py` ยังเป็นค่าที่ตั้งไว้ ยังไม่ได้ปรับจากข้อมูล)

1. **สั่น (tremor):** ข้อมือนิ่ง และพลังงานส่วนใหญ่อยู่ในช่วง 3.5–7.5 Hz ไม่จำกัดความแรง
2. **เดิน (walk):** ไม่ใช่หน้าต่างสั่น เป็นจังหวะสม่ำเสมอแบบรอบการเดิน และขยับแรงพอ
3. **พัก (rest):** ไม่ใช่เดิน ข้อมือนิ่ง ขยับเบา หรือขยับเพราะสั่นอย่างเดียว (หน้าต่างสั่นนับเป็นพักด้วย)
4. **อื่น ๆ:** ไม่เข้าทั้งเดินและพัก เช่นทำงานบ้าน ขยับแขนไม่เป็นจังหวะ

ไม่มีป้ายวิ่ง นั่ง หรือยืน การวิ่งจะถูกนับเป็นเดิน

## 5. สิ่งที่ต้องระวังตอนเทรน

### 5.1 label ซ้อนกับยี่ห้อนาฬิกา 100%
PD ทุกคนใส่ GENEActiv คนปกติทุกคนใส่ ActiGraph โมเดลอาจแยกยี่ห้อแทนการแยกโรค และดูจาก accuracy อย่างเดียวจะไม่รู้ตัว

- สิ่งที่ทำไปแล้ว: ปรับ noise และความละเอียดของค่าให้เท่ากันตั้งแต่ขั้น clean และตัด feature ที่มีลายเซ็นเครื่องชัด
- ที่ยังเหลือ: feature ส่วนใหญ่ยังแยกสองชุดได้บางส่วน และข้อมูลชุดนี้แยกไม่ออกว่ามาจากโรคหรือจากเครื่อง
- **ถือว่าผลบน COPS vs NHANES เป็นค่าเพดาน** ต้องรายงานคู่กับผลบนชุดทดสอบที่ยี่ห้อไม่ซ้อนกับโรค (หัวข้อ 7)

### 5.2 แบ่งข้อมูลตามคน
- ใช้คอลัมน์ `split` ห้ามสุ่มแบ่งรายชั่วโมงหรือรายวัน (คนเดียวกันจะอยู่ทั้ง train และ test)
- cross-validation ใน train ใช้ GroupKFold ตาม `subject_id`
- label เป็นของทั้งคน ประเมินผลโดยรวมผลทำนายเป็นรายคน

### 5.3 ค่ากลางจาก train เท่านั้น
ค่าเฉลี่ย / SD สำหรับ standardize, ค่าที่ใช้เติม NaN, การเลือก feature และการปรับเกณฑ์ ใช้เฉพาะ train

### 5.4 NaN
- NaN แปลว่า "ชั่วโมงนั้นไม่มีหน้าต่างประเภทที่ต้องใช้" เช่นชั่วโมงที่ไม่ได้เดินจึงไม่มีจังหวะก้าว
- **ห้ามเติม 0** (จังหวะก้าว 0 ไม่มีความหมาย)
- COPS มี NaN ในกลุ่มการเดินมากกว่า NHANES เพราะเดินน้อยกว่า ถ้าไม่ระวังโมเดลจะเรียนจากรูปแบบ NaN แทนค่าจริง

### 5.5 ค่าสุดโต่ง
คนไข้บางคนมีค่า tremor สูงกว่าคนอื่นมาก โมเดลเชิงเส้นอาจให้ผลกลับข้าง ควร clip ค่าหลัง standardize หรือใช้โมเดลที่ทนค่าสุดโต่ง

### 5.6 feature ที่ควรระวังเป็นพิเศษ
- **`spec_entropy_median`, `dom_freq_rest_median`, `tremor_rms_rest_p90`:** ในหน้าต่างที่ขยับน้อย noise ของเครื่องมีผลมาก จึงไวต่อยี่ห้อ เคยเห็นโมเดลให้น้ำหนัก `tremor_rms_rest_p90` กลับทิศ (แรงสั่นสูง = คนปกติ) ลองเทรนแบบตัดออกเทียบด้วย
- **กลุ่ม ⚠:** ไวต่อยี่ห้อมากกว่ากลุ่มสัดส่วน มุม และความถี่
- **feature tremor:** ตัวจับยังจับผิดในคนปกติอยู่บ้าง
- **feature ที่สัมพันธ์กับความรุนแรงของโรคใน COPS** (เครื่องเดียวกัน จึงน่าจะเป็นสัญญาณโรคจริง): `walk_frac`, `stride_reg_walk_median`, `step_freq_walk_sd`, `jerk_p90`

### 5.7 ข้อมูลน้อย
จำนวนคนมีไม่มาก ใช้โมเดลเล็ก ใช้ regularization และเทียบกับ baseline ง่าย ๆ เสมอ เช่น logistic regression ระดับคน

## 6. แนวทางเตรียมข้อมูลเข้า LSTM

ใช้ข้อมูลระดับชั่วโมงเรียงเป็นลำดับเวลา

1. **ลำดับ:** 1 วันของ 1 คน = 1 ลำดับ 12 ชั่วโมง (09:00–21:00) แบ่งด้วย `subject_id` + `day` เรียงด้วย `hour`
2. **label:** ทุกวันของคนเดียวกันใช้ label เดียวกัน ตอนประเมินเฉลี่ยผลทุกวันของคนนั้น
3. **ชั่วโมงที่หายไปทั้งชั่วโมง:** ใส่ 0 แล้วใช้ mask ให้ LSTM ข้าม
4. **feature ที่เป็น NaN:** เติมด้วย median ของคนนั้นเอง ถ้าไม่มีใช้ median ของ train และเพิ่ม flag 0/1 บอกว่าค่าถูกเติม
5. **standardize** ด้วยค่าจาก train แล้ว clip ค่าสุดโต่ง
6. ไม่ใส่ชั่วโมงของวันหรือเลขวันเป็น feature

LSTM เห็นจังหวะของทั้งวัน จึงอาจเรียนความต่างของตารางชีวิตระหว่างสองชุดได้ ต้องตรวจตามหัวข้อ 7 ด้วย

| ชั่วโมงนอนหลุดเข้ามา | ตัวจับการนอนพลาดช่วงกลางคืนของ PD ทำให้ COPS ดูขยับน้อยเกินจริง | ใช้เฉพาะ 09:00–21:00 |
| correlation ระหว่างแกน | noise ของ GENEActiv สัมพันธ์ระหว่างแกน แยกยี่ห้อได้แม้ไม่มีคนใส่ | ตัด `corr_*` |
| feature ที่ไม่มีประโยชน์ | `still_frac` เป็นศูนย์เสมอหลัง clean, `swing_walk_sd` เป็น NaN เกือบทั้งหมด | ตัดทั้งสองตัว |

**ทดสอบแล้วว่าไม่ต้องทำ**
- **Low-pass ก่อนคำนวณ feature:** ไม่ลดการแยกยี่ห้อ และทำให้ตัวจับ tremor จับผิดมากขึ้น
- **แก้ calibrate ของ NHANES:** ตัวเลข error ใน QC สูงเพราะ ActiGraph หยุดวัดตอนนิ่ง (เขียนค่าเดิมซ้ำ) ช่วงนั้นถูกตัดก่อนขั้น feature อยู่แล้ว และไม่กระทบ `swing`
- **ปรับการปรับ noise ในขั้น clean:** ระดับ noise และความละเอียดของค่าสองชุดเท่ากันแล้ว
